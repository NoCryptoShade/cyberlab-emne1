01 Hvem passer på tabellen?
Lett▶
Nivå 1 — Fil eller database?

I L19 lagde du en CSV-rapport. Den er bare en fil, og alle kan rote i den. Hva om noen passet på tabellen for deg? 🛡️

Du åpner den i Notisblokk og leser alt som vanlig tekst.
Du åpner den i Notisblokk og ser bare rare tegn 🤯
Den nekter å lagre to rader med samme id.
Hver linje er én rad. Verdiene står skilt med komma.
Du spør «bare de feilede, nyeste først», og får akkurat det.
Programmet ditt må lese hele fila, linje for linje, for å finne noe.
To programmer skriver samtidig. Motoren lar dem ta tur, så ingenting blandes.
📌 Fagord En database er data i tabeller. En databasemotor (database engine) passer på dem: følger reglene, lar mange bruke dataene og svarer på spørsmål.
Spørsmålene skrives i SQL (Structured Query Language). Ett spørsmål heter en spørring (query).
Vi bruker SQLite: Hele databasen er én fil, logg.db. Kommandoen heter sqlite3.

🏢 Store databaser som MySQL og PostgreSQL kjører som en egen server, med brukere, passord og rettigheter. SQLite har ikke brukere: Den som kan lese fila, kan lese alt.

Nivå 1 — Et regneark med regler

En tabell er et regneark med strenge regler 📊 Her er tabellen brukere. Finn tre ting i den.

id  navn    rolle
--  ------  ------
1   kari    admin
2   ola     bruker
3   petter  bruker
4   test    bruker
📌 Fagord Tabell (table) = ett regneark. Rad (row) = én ting, her én bruker. Kolonne (column) = én egenskap, som rolle.
Primærnøkkel (primary key) = kolonnen som er unik for hver rad, oftest id. Motoren nekter to like.
SELECT * FROM brukere; = «vis alle kolonner (*) fra tabellen brukere». ; avslutter setningen.

03 Bare radene der …: WHERE
Middels▶
Nivå 2 — Spør presist

Databasen er et orakel 🔮 Den svarer på akkurat det du spør om, verken mer eller mindre. Hvilken spørring passer til spørsmålet?

Alle starter med SELECT * FROM innlogginger og slutter med: AWHERE resultat = 'FEIL'; BWHERE bruker = 'root'; CWHERE ip LIKE '192.168.%'; DWHERE tid > '09:13:00';
Vis alle innloggingene som feilet.
Hva har skjedd med kontoen root?
Hvem logget inn fra vårt eget nett, 192.168.noe?
Hva skjedde etter klokka 09:13?
Angriperen gikk etter superbrukeren. Finn de radene.
📌 Fagord WHERE = «bare radene der …». Sammenlign med = (helt lik), > (større enn) eller LIKE (ligner på). I LIKE betyr % «hva som helst».
AND = begge må stemme. Tekst står i enkle anførselstegn: 'FEIL'

🦹 Se på de enkle anførselstegnene rundt 'root'. Hva om en angriper skriver sin egen ' i et søkefelt? Det heter SQL-injeksjon (SQL injection), og kommer i L22.

Nivå 2 — ORDER BY, LIMIT og COUNT

Sjefen gidder ikke lese hele loggen: «Gi meg de tre nyeste. Og hvor mange feilet?» ⏱️ Hvilken bit gjør hva?

SELECT tid, ipVis bare disse kolonnene
ORDER BY tidSorter, eldst først
ORDER BY tid DESCSorter, nyest først
LIMIT 3Bare de tre første radene
COUNT(*)Tell radene
📌 Fagord ORDER BY sorterer. DESC (descending) = synkende, størst eller nyest først. LIMIT begrenser antall rader. COUNT(*) teller.
De kan kombineres med WHERE: WHERE først, så ORDER BY, og LIMIT helt til slutt.

05 Verstingen på én linje: GROUP BY
Middels▶
Nivå 2 — Telle per IP

Husker du tell_ip.py fra L17? Sju linjer Python for å telle feil per IP. Databasen klarer det med én spørring 😎

SELECT ip, COUNT(*)
FROM innlogginger
WHERE resultat = 'FEIL'
GROUP BY ip
ORDER BY COUNT(*) DESC
LIMIT 1
📌 Fagord GROUP BY ip samler radene i grupper, én per IP. COUNT(*) teller da hver gruppe for seg.
Rekkefølgen er fast: SELECT · FROM · WHERE · GROUP BY · ORDER BY · LIMIT

Nivå 2 — Endre data

Til nå har du bare lest. Nå skal du endre. Og her biter det 🔥

📍 Fredag kl. 15.52. Kontoret er nesten tomt.
Petter, kan du gjøre testbrukeren til gjest før helga?
Klart! Én linje: UPDATE brukere SET rolle = 'gjest'; ⏎
sqlite3 svarer ingenting. Ingen feil, ingen «Er du sikker?»
Stille betyr at det gikk bra. God helg! 🏃
kari gjest · ola gjest · petter gjest · test gjest
Hvorfor er JEG gjest?! Jeg kommer ikke inn i adminpanelet 😱
Øh … jeg glemte WHERE. Da gjaldt den alle fire radene.
Heldigvis har vi backup fra torsdag 😮‍💨 Riktig linje var UPDATE brukere SET rolle = 'gjest' WHERE navn = 'test';
Ny lapp over skjermen min: 📝 «WHERE først!»
📌 Fagord INSERT INTO legger til en rad. UPDATE … SET endrer rader. DELETE FROM sletter rader.
Uten WHERE treffer UPDATE og DELETE hver eneste rad i tabellen.

✅ Proff-vane: Kjør SELECT * med samme WHERE først. Er det de riktige radene? Først da bytter du til UPDATE eller DELETE.
