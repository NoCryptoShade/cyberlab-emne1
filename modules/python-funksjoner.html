01 Oppskriftskortet: def og kall
Lett▶
Nivå 1 — Gi koden et navn

Tenk deg et oppskriftskort 📇. Du skriver det én gang, setter et navn på det, og legger det i skuffen. Når du trenger det, sier du bare navnet. Men når skjer hva?

def hils():
    print("Hei fra funksjonen 👋")

print("Start")
hils()
print("Slutt")
📇 Python leser def hils(): og legger kortet i skuffen
🖨️ Skjermen viser «Start»
📞 hils(): Python hopper inn i funksjonen
👋 Skjermen viser «Hei fra funksjonen»
↩️ Python hopper tilbake dit kallet sto
🖨️ Skjermen viser «Slutt»
📌 Fagord En funksjon (function) er kode med et navn. def lager den: navn, parenteser og kolon, og innrykk under, som med if i L16. Å bruke den heter å kalle den (call): hils()

02 Ingredienser: parametre og argumenter
Lett▶
Nivå 1 — Samme oppskrift, nye ingredienser

Pannekakeoppskriften virker med 2 egg og med 4 🥞 En funksjon kan også få nye «ingredienser» hver gang du kaller den.

def varsle(ip, niva="🟡"):
    print(niva, "Sjekk", ip)
varsle("203.0.113.45")🟡 Sjekk 203.0.113.45
varsle("203.0.113.45", "🔴")🔴 Sjekk 203.0.113.45
varsle("198.51.100.23", "🟠")🟠 Sjekk 198.51.100.23
varsle("🔴", "192.168.1.10")192.168.1.10 Sjekk 🔴
📌 Fagord ip og niva i def-linja er parametre (parameters): tomme plasser i oppskriften. Verdiene du sender med i kallet, er argumenter (arguments). De fylles inn i samme rekkefølge.
niva="🟡" er en standardverdi (default value). Den brukes når du ikke sender med noe.

03 print eller return?
Middels▶
Nivå 2 — Å få svaret tilbake

To funksjoner regner ut det samme. Den ene roper svaret ut på skjermen 📢. Den andre gir det til deg 🎁. Bare én av dem kan du bruke videre.

def med_print(a, b):
    print(a + b)

def med_return(a, b):
    return a + b
x = med_return(2, 3)
x = med_print(2, 3)
x = med_return(5, 5)
x = med_print(4, 6)
x = med_return(2, 3) * 2
x = med_return(1, 4)
📌 Fagord return gir en verdi tilbake til den som kalte funksjonen. print viser bare noe på skjermen. En funksjon uten return gir tilbake None, Pythons «ingenting».
Variabler laget inni en funksjon er lokale (local variables). De forsvinner når funksjonen er ferdig. return er den vanlige veien ut.

04 Lån fila, lever den tilbake: with
Middels▶
Nivå 2 — Filer på den trygge måten

I L16 åpnet du auth.log med open(). Men hvem lukket den igjen? 🚪

📍 les2.py vil lese auth.log
with open("auth.log") as f: Kan jeg låne auth.log? Jeg kaller den f.
Værsågod, fila er åpen. Husk å levere den tilbake 🙏
for linje in f: Én linje om gangen, takk. Accepted… Failed… Failed…
…Connection. Det var den siste. Blokken med innrykk er ferdig.
🚪 with lukker fila automatisk. Ingen trenger å huske noe.
Fila er levert tilbake 👍
Og hvis noen skriver feil filnavn? Da finnes ikke jeg 😈
📌 Fagord with open("auth.log") as f: åpner fila og gir den navnet f. Når blokken med innrykk er ferdig, lukkes fila automatisk, også om programmet krasjer inni. Med bare open() må du huske f.close() selv.
for linje in f gir én linje om gangen. f.read() gir hele fila som én lang tekst.

🔥 Et program som åpner filer i en løkke uten å lukke dem, kan gå tom for filhåndtak. Da stopper det med «Too many open files». Et klassisk problem i loggverktøy som kjører lenge.

05 Alt sammen: tell_feil(filnavn)
Middels▶
Nivå 2 — Én funksjon, to logger

Gårsdagens logg ligger i auth.log.1. Kopiere tell.py og bytte filnavn? Nei! Gjør tell.py til et oppskriftskort, og la filnavnet være ingrediensen 📇

def tell_feil(filnavn):
    antall = 0
    with open(filnavn) as f:
        for linje in f:
            if "Failed password" in linje:
                antall += 1
    return antall

nye = tell_feil("auth.log")
gamle = tell_feil("auth.log.1")
print("Totalt:", nye + gamle)
📌 Fagord Nå er tell_feil et verktøy: filnavn inn, tall ut. Argument inn → funksjon → returverdi ut. Det mønsteret går igjen i nesten alle Python-skript du kommer til å lese.
